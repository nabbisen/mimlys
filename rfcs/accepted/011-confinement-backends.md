# RFC 011 — Confinement backends and host tools

**Status.** Accepted (2026-10-29; the seven questions of the review package decided as recommended). Shipped in 0.7.0: §1–§3 and §6–§10 (the Linux and Windows backends, host tools, the dependency step, orphans, tests); open: §4 (macOS) and its use of §5 accepted best-effort (M6c, release 0.8; Amendment 2). The Windows demonstration of §10 (`cargo test --offline`) is not met on Windows in 0.7.0: `cargo` cannot run in an AppContainer (the `NUL` device, refused on Windows Server 2022 and 2025 alike); a spike on 2026-11-03 found no remedy that keeps clauses F, N and P, so it is an exception without a remedy (see external design §23).
**Tracks.** Decisions D-06 v2 and D-07 v2 of the startup review; the cross-platform confinement assessment (`05-cross-platform-confinement-assessment.md`); findings R-05, R-06, R-07, R-13, R-16, R-18; threats THR-11, THR-17, THR-23, THR-24, THR-32.
**Touches.** `mimlys-exec` (the confinement backends per platform, the worker's self-confinement, `run_host_tool`), `mimlys-core` (host-tool declarations, the `host_tool` grant's validation, the probe's new states), `mimlys` (`[host_tools.<name>]`, `[policy] accept_best_effort`, `mimlys toolchain`, `status`), external design §13, §11, §19.1, §19.2, §20, §23 (M6a–c); requirements REQ-CONF-001 … 010, REQ-TEST-013; limits LIM-H1 … H4.
**Milestones.** M6a Linux (release 0.6), M6b Windows (0.7), M6c macOS (0.8): one contract, one backend per platform, one handoff each.

## Summary

The confinement contract of REQ-CONF-001 is implemented by the **worker confining itself** at start from a specification the runtime passes: the read and write sets, the toolchain paths, the limits and whether network is denied. Each platform's backend applies its primitives inside the worker process before any request is read, and the worker reports per clause what took effect: `enforced`, `best_effort` or `unavailable{reason}`. The runtime's probe at startup is that report from a real worker, so the status is never a guess. Host tools exist only as administrator declarations (`[host_tools.<name>]`: a fixed command, fixed arguments, an allow-list for the model's arguments, the effect, the deadline, the toolchain read paths, the environment), run as children of the confined worker in the task's workspace, and are visible only with a `host_tool` grant and only when every mandatory clause is enforced (or, for one clause the platform cannot enforce, when the administrator accepted best-effort for it explicitly and visibly). Host tools run offline; dependency fetching is a declared host tool with `network = true`, run by a one-shot worker whose confinement keeps every clause but N, approval-gated as `external_read`. Each platform ships with the clause tests of REQ-TEST-013 in CI and the demonstration of external design §23: `cargo test --offline` of a native project under every mandatory clause.

## Motivation

- "Fix the failing test" needs the project's own toolchain (R-05, R-06): a compiler and a test runner execute project code with the user's privileges, so they must run under the contract or not at all (THR-23).
- The worker exists since M2 as the outer layer of the sandbox (D-10); its process group and explicit environment are the clauses E and K already. M6 fills F, N, P, M and C per platform, in the staged order the owner confirmed (Linux, Windows, macOS).
- Every platform has unprivileged primitives for the contract (assessment §3); the differences are in strength and effort, which the status must state rather than hide (D-06 v2 §3: probe and fail closed).

## Decision

The normative text is external design §13 (revised by this RFC), §11 (`run_host_tool`), §19.1 (`[host_tools]`), §20, §23; requirements REQ-CONF-001 … 010, REQ-CAP-002 (`host_tool`), REQ-TEST-013; limits LIM-H1 … H4. In brief:

1. **The worker confines itself (REQ-CONF-002, REQ-CONF-010).** The runtime spawns the worker with a `ConfinementSpec`: `read_paths` (the data directory, the temp directory, the declared toolchain paths, the platform's system paths), `write_paths` (the workspaces directory, the temp directory), `network: deny | allow`, `memory_bytes` (LIM-H2), `max_processes` (LIM-H3), and the worker applies the platform backend **before reading its first frame**, while still single-threaded, through safe crates where they exist (`landlock`, `seccompiler`, `rustix` on Linux) and through the justified `unsafe` of `mimlys-exec::confine` elsewhere (REQ-CONF-010). What the backend could not apply is reported, not hidden: the `probe_result` of the worker protocol carries every clause's state and reason, and `get_runtime_status` shows it. No `pre_exec` hooks in the runtime: the process that is confined is the one that reports it.
2. **The ladder per clause, Linux (M6a).** F: Landlock (ABI 1 and up; the read set as `ReadFile`/`ReadDir`, the write set as `WriteFile`/`MakeReg`/`MakeDir`/`RemoveFile`…; `enforced`), else `unavailable{landlock}`. N: a network namespace (`unshare(CLONE_NEWNET)` inside a user namespace when unprivileged user namespaces are allowed) **and** a seccomp filter denying `socket` for every family but `AF_UNIX`; `enforced` when either holds (the filter alone is enough), `unavailable{seccomp}` when neither. E: the explicit environment of M2 (`enforced`). K: a PID namespace when user namespaces are allowed, else the worker as **child subreaper** (`PR_SET_CHILD_SUBREAPER`) with a `/proc` walk that kills every descendant until none remains, within LIM-O2 (`enforced`: re-parenting cannot escape a subreaper); `cgroup.kill` of a delegated cgroup when one is writable (preferred, `enforced`). P: `no_new_privs` and the seccomp filter (also denying `ptrace`, `mount`, `keyctl`, `bpf`, `unshare` after the setup) (`enforced`). M: `memory.max` of a delegated cgroup (`enforced`), else `RLIMIT_AS` per process (`best_effort`). C: `pids.max` of a delegated cgroup (`enforced`), else `RLIMIT_NPROC` (`best_effort`); the wall clock is the runtime's timer (`enforced`). The backend tries the stronger primitive first and records which held; the clause table in `status` names the primitive (`enforced (landlock)`, `best_effort (rlimit_as)`).
3. **Windows (M6b).** F and N: the worker runs in an **AppContainer** without the network capabilities (`CreateAppContainerProfile` with a profile name derived from the data directory; `PROC_THREAD_ATTRIBUTE_SECURITY_CAPABILITIES`); the workspaces directory and the temp directory carry ACEs granting the container SID write, the declared toolchain paths read, applied by `mimlys toolchain grant` (point 7) and reverted by `revoke`; `enforced`. E: explicit block with `TEMP`, `TMP`, `USERPROFILE`, `LOCALAPPDATA`, `CARGO_HOME` redirected into the task's workspace or temp. K: the Job Object of M2 (kill-on-close, breakaway forbidden; `enforced`). P: a restricted token (`CreateRestrictedToken`, `DISABLE_MAX_PRIVILEGE`, low integrity) (`enforced`). M and C: Job Object limits (`JobMemoryLimit`, `ActiveProcessLimit`, `enforced`). Because the AppContainer is applied at spawn by the parent, the Windows worker is spawned confined by the runtime (the one platform where the parent must act) and still reports what it finds itself in.
4. **macOS (M6c).** F, N, P: a **Seatbelt** profile (`sandbox_init` with a generated profile: `(deny default)`, `(allow file-read* …)` for the read set, `(allow file-write* …)` for the write set, `(deny network*)`, `(allow process-exec …)` for the toolchain paths; `enforced`; the deprecated API is wrapped once, with a startup check that it still functions). E: explicit environment. K: the process group of M2 plus a descendant walk (`proc_listchildpids`) repeated until none remains within LIM-O2, **`best_effort`** (no subreaper on macOS; a re-parented orphan escapes the walk). M: a resident-size watchdog that kills the tree above LIM-H2 (`best_effort`). C: `RLIMIT_NPROC` (`best_effort`), the runtime's timer.
5. **Tier, fail closed, and accepted best-effort (REQ-CONF-003, REQ-CONF-004).** Host tools are visible and runnable only at tier `full`: every mandatory clause `enforced`. Because macOS cannot enforce K, the administrator may accept best-effort for named clauses: `[policy] accept_best_effort = ["K"]`; the tier is then `full (K best-effort, accepted)`, `status` says so on its own line, and every approval prompt of a host tool carries the same line. Nothing is accepted by default; an `unavailable` clause can never be accepted. This is explicit, visible degradation under the administrator's signature, not silent degradation.
6. **Host tools (REQ-CONF-006, REQ-CONF-008).** `[host_tools.<name>]`: `command` (an absolute path, or a name resolved against the declared toolchain paths only, never the inherited `PATH`), `args` (fixed), `allowed_args` (literal arguments the model may add), `arg_pattern` (a regular expression any further argument must match; absent means none), `max_args`, `effect` (`workspace_write` for a tool that writes only inside the workspace, reversible through the snapshots; `host_write` with `reversible = false` for a tool that writes declared host paths), `timeout_ms` (LIM-H1), `read_paths` (toolchain and cache directories, `~` expanded), `env` (fixed variables), `env_allow` (copied from the runtime's environment), `network` (default false; true makes the tool the dependency step of point 8). `run_host_tool{tool, args?}` is validated at stage 5 against the declaration (each argument a literal of `allowed_args` or a match of `arg_pattern`; at most `max_args`; no shell, no `..`, no absolute path unless the pattern allows it), at stage 7 against the task's `host_tool{name}` grant, and runs with the workspace tree as its working directory, its stdout and stderr captured to LIM-H4 each. The tool's declared read paths join the worker's read set at startup; the union over all declared tools is what the worker can see, and `status` lists it (REQ-CONF-008).
7. **Toolchain visibility, reversible (REQ-CONF-008).** `mimlys toolchain list` shows the read paths in force and, on Windows, whether their ACEs are applied; `mimlys toolchain grant <path>` / `revoke <path>` apply and remove, with confirmation, the ACEs for the container SID on Windows and record them under the data directory so that `revoke` and an uninstall leave the user's profile as it was; on Linux and macOS the commands only show the paths (Landlock and Seatbelt need no change to the directories). A declared `read_paths` entry that is not applied on Windows makes that tool unavailable with the reason `acl_not_applied`, never a silent failure at run time.
8. **The offline rule and the dependency step (REQ-CONF-007).** Host tools run under clause N. A declared tool with `network = true` (`cargo fetch`, `npm ci --ignore-scripts`, …) is the dependency step: effect `external_read`, approval per profile like any external effect, run by a **one-shot worker** spawned for that execution with `network: allow` and every other clause as usual, ended when the execution ends. The book states plainly that `cargo test` runs with `--offline` and that fetching is a separate approved step.
9. **Orphans and startup (REQ-CONF-009).** The worker's tree handle (cgroup path, process group, Job Object name) is recorded under the data directory while it lives; at startup the runtime terminates what a previous runtime left (a cgroup still populated, a process group whose leader's start time matches the record) and records `runtime.orphans_killed{count}` when it did.
10. **Tests and demonstration (REQ-TEST-013, external design §23).** Per platform, in CI on that platform: for every clause the probe reports `enforced`, a host tool that tries the forbidden thing fails in the expected way (read `/etc/shadow` or `C:\Windows\…` outside the set, write outside the workspace, open an `AF_INET` socket and a loopback connection, read an inherited variable, `setsid` and sleep then be killed on cancel, a setuid binary gain nothing, allocate past LIM-H2, fork past LIM-H3); an injected failure (`MIMLYS_PROBE_FAIL`) makes host tools unavailable with the reason; the demonstration runs `cargo test --offline` of a native project in the workspace with the toolchain read paths declared, ends `completed{verified}` through a `run_host_tool` completion check, and the clause table of `status` is printed into the report.

## Alternatives considered

- Confinement applied by the runtime in `pre_exec` before `exec`: the standard pattern, but it is `unsafe` code in the parent, cannot report what held, and the Windows AppContainer cannot be applied that way at all. Rejected except where the platform requires the parent to act (Windows).
- A mount namespace with a minimal root on Linux (the bubblewrap model): stronger isolation, but it depends on unprivileged user namespaces, which Ubuntu 24.04 and other distributions restrict, and the read set is what Landlock expresses directly. Rejected as the base; the namespaces are used opportunistically for N and K.
- Process groups alone for K on Linux: escapable with `setsid` (assessment §3). Rejected; the subreaper walk or a PID namespace or `cgroup.kill`.
- Letting the model pass arbitrary arguments to a host tool: a shell by another name. Rejected; literals and a declared pattern.
- Treating macOS K as `enforced`: dishonest. Rejected; `best_effort`, accepted only by configuration and shown everywhere.
- Running the dependency step unconfined in the runtime process: it would run project build scripts with network and no F. Rejected; the one-shot worker keeps every clause but N.

## Consequences

- `mimlys-exec` gains `confine/linux.rs` (Landlock, seccomp, namespaces, cgroup, subreaper), `confine/windows.rs` grows (AppContainer, restricted token, ACLs), `confine/macos.rs` (Seatbelt, the watchdog); the worker gains the self-confinement step and `run_host_tool`; `Probe` states carry the primitive's name.
- `mimlys-core` gains `HostToolDeclaration`, the validation of `run_host_tool` arguments, `host_tool` grants' use, `Tier` with the accepted-best-effort form, the event `runtime.orphans_killed{count}`.
- Configuration: `[host_tools.<name>]`, `[policy] accept_best_effort`, `[policy.ceiling] host_tools` (exists); the command `mimlys toolchain list|grant|revoke`.
- New limits: none (LIM-H1 … H4 exist); LIM-O2 bounds the kill walk.
- Documentation: the book gains "Host tools: fixing a failing test" with the offline rule, the toolchain paths, the Windows ACL step, and what the tier line means; the M6 report per platform.

## Open questions

- None at the RFC level; each handoff's §7 records what the platform taught during implementation.

## Amendment 1 — Linux hardening (2026-11-03, release 0.7.1)

The intake review after 0.7.0 found two defects in the Linux backend as shipped (`.git-exclude/reviewed/intake-0.7.0/README.md`, N-01 and N-02). The decisions above stand; these amend points 2, 6 and 7:

1. **Clause N has two layers, and the first was incomplete.** A seccomp filter on `socket` does not see sockets created by `io_uring` (`IORING_OP_SOCKET`, Linux 5.19 and later; reproduced). The filter now always denies `io_uring_setup`, `io_uring_enter` and `io_uring_register` (the dependency step's worker too: it needs no ring) and `process_vm_readv` and `process_vm_writev` (cross-process memory, which `ptrace`'s denial did not cover). Where Landlock ABI 4 exists and network is denied, TCP `bind` and `connect` are handled with an empty allow-set; UDP stays with seccomp. The N cell reads `seccomp+landlock_net` when both hold, `seccomp` otherwise.
2. **Other processes are not part of the read set.** `/proc` is no longer readable as a whole: `/proc/<pid>/environ` of the runtime (and of an MCP server child) held `env:`-referenced secrets. The set keeps only the `/proc` files a toolchain proves it needs; the runtime and the worker are non-dumpable (`PR_SET_DUMPABLE` 0), which closes `/proc/<pid>/{environ,mem,fd}` and `process_vm_readv` for the processes that matter most. (Correction after the review of handoff 011d: Landlock's ptrace scoping already refuses a confined process another process's `environ`, `maps`, `fd` and `mem`, so what the narrowing removes is `cmdline`, `status`, `stat` and the network tables; and the worker keeps `/proc` for its descendant walk while each host tool's process is restricted to the same sets without it, as a second Landlock layer.) Removing a variable from the runtime's own environment was considered and rejected: `/proc/<pid>/environ` keeps the environment the process started with. An MCP server child is `exec`'d and dumpable again; its environment is protected by the host tools' read set, not by a flag.
3. **A declared read path may not contain credentials.** `read_paths = ["~/.cargo"]` made `~/.cargo/credentials.toml` readable to project code. A declared path that is a root, the home directory or an ancestor of it, or that directly holds a name of LIM-H5, is refused with the narrower path suggested (`~/.cargo/bin`); the same check guards `toolchain grant` on Windows. Landlock has no deny rule, so the check is on the declaration, not in the kernel. `/etc` and `/opt` stay readable as a whole; the residual is stated in the threat register.
4. **Open, for a later handoff:** Windows lifecycle (a command that removes the container profile and every entry; THR-36), and the same read-set question for macOS in 011c.

Requirements REQ-CONF-011 and REQ-CONF-012, limit LIM-H5 and threat THR-36 carry the normative text; external design §13.3 and §13.5 are amended. Handoff 011d executes this amendment; it changes no contract of the control API, the CLI or the configuration beyond the new refusal in point 3.

## Amendment 2 — the macOS backend, from spike S1 (2026-11-07, release 0.8)

Spike S1 (`.git-exclude/review-requests/S1-macos-seatbelt/README.md`; macOS 26.7.2, arm64, `macos-latest`, four CI runs) measured what point 4 assumed. Point 4 is replaced by the following. Marked **[S1b]**: decided in principle, settled by the short follow-up spike S1b before that part is implemented.

1. **One profile for the worker and its tools.** A sandboxed process can apply no second profile, to itself or to a child (`sandbox_init` again: `EPERM`; `sandbox-exec` inside a profile aborts; measured). The Linux two-layer design (Amendment 1, point 2 correction) cannot be copied. The worker applies one Seatbelt profile to itself before its first frame, and every host tool inherits it. Applying profiles only to tools and leaving the worker unconfined was considered and rejected: the worker runs the Wasmtime guest, and REQ-CONF-002 keeps the worker confined (THR-17). Consequence: what the worker needs, its tools have; the profile is therefore built from the tools' needs, and the worker adds nothing that shows other processes (point 4).
2. **`sandbox_init` is resolved at run time** (`dlsym`), so a macOS that removes it reports F, N and P `unavailable{seatbelt_missing}`; after applying, the worker checks itself (a read the profile denies must fail) and reports `unavailable{seatbelt_ineffective}` otherwise. Neither is ever a crash. A profile the system rejects reports its message (`sandbox_init` gives it with a position).
3. **The profile.** `(deny default)`; the read set `file-read*` and `process-exec` (canonical paths: `/tmp`, `/var`, `/etc` resolve into `/private`; strings escaped); the write set `file-write*` and `file-read*`; no network (`(deny network*)`), Unix sockets only under the write set and as unnamed pairs; DNS is refused (it is a mach service and a Unix socket, and an egress channel: measured); no rule for the JIT (Wasmtime runs under `(deny default)` without one: measured).
4. **Other processes are invisible.** `(deny process-info*)` then `(allow process-info* (target same-sandbox))`; `(allow signal (target same-sandbox))`; `(allow sysctl-read)` then `(deny sysctl-read (sysctl-name-prefix "kern.procargs"))`, the one form that refuses another process's environment through `KERN_PROCARGS2` (measured; the `sysctl-name` form does not). An unconfined same-user program can still read the runtime's environment that way; macOS offers no refusal of it, and it is stated as a residual (threat register).
5. **P is `enforced (seatbelt)`.** The kernel refuses a setuid `execve` from a sandboxed process (a setuid-root `id` and `sudo` both `EPERM` inside, `0` outside; measured). No rule is needed; a clause test asserts it.
6. **K by sandbox membership [S1b].** A re-parented orphan (`setsid`, double fork, parent `launchd`) stays a member of its sandbox and can be signalled by the worker; another worker that applied the same profile text is a different sandbox and cannot (measured). The worker starts no process but the current host tool, one at a time (LIM-X2), so the members other than the worker are exactly the tool's tree. Design: after a cancel, a deadline or a tool's end, the worker sends `kill(-1, SIGKILL)`, which the profile restricts to members and the kernel never sends to the caller; before relying on it the worker verifies the restriction (signalling `launchd` and the runtime must both fail `EPERM`), else K is `unavailable{membership_unverified}`. Primitive `seatbelt_membership`, **`enforced`**. S1b measures `kill(-1, SIGKILL)` inside the profile; if it reaches anything outside, K falls back to the process group and the members the worker can name, `best_effort (process_group_walk)`, and the tier needs `accept_best_effort = ["K"]` as point 5 of the decision says.
7. **M and C [S1b].** Resident size is readable for members (measured). Listing them without listing every pid on the machine is the open question: if S1b finds a listing restricted to the sandbox, M is `rss_watchdog` and C `process_count_watchdog` over the members, both `best_effort`, polled every LIM-H6; otherwise M watches the host tool's own process and C is the wall clock, both `best_effort`, and the report says so. The tools are never given `process-info-listpids` for the whole machine. `RLIMIT_NPROC` (point 4 of the decision) is not used: it counts every process of the user.
8. **The read set [S1b].** The system part: `/usr`, `/bin`, `/sbin`, `/System` (frameworks and the dyld cache under `/System/Volumes/Preboot/Cryptexes`), `/private/etc` as a whole (as `/etc` on Linux, a stated residual), the random, zero and null devices, and the **active developer directory** (where `cc` and `ld` live), which the runtime reads from the `/private/var/db/xcode_select_link` link without running a command, falling back to `/Library/Developer/CommandLineTools` when it exists, shown by `toolchain list`. The declared part as everywhere, canonicalized; a `command` whose resolved target leaves the read set (Homebrew's `rustup` links into `/opt/homebrew/Cellar/…`) is refused at load, naming the resolved path to declare. Files in the home directory (the global preferences, `~/.CFUserTextEncoding`) and mach services are admitted only one by one, if S1b shows that `cargo test --offline` fails without them, as literal files or named services, each with its reason; a mach service that can reach the network or the user's secrets on the caller's behalf is never admitted (`com.apple.trustd`, `nsurlsessiond`, `securityd` and the like).
9. **The dependency step** keeps its own worker and its own sandbox (a different sandbox, so point 6 stays exact), whose profile adds outbound TCP and the two DNS services; the minimum is S1b's.

External design §13.3's macOS row is amended to match; LIM-H6 stays provisional until the implementation's measurements. Handoff 011c §4 executes this amendment.

### Amendment 2, settled (2026-11-07, from spike S1b and the 011c-1 slice)

S1b (`.git-exclude/review-requests/S1b-macos-seatbelt/README.md`, three CI runs) and the first implementation slice (`…/011c-1-macos/README.md`) measured the points marked [S1b]. Where this section and the points above differ, this section governs.

- **Point 4, corrected:** both rules are needed together to refuse another process's `KERN_PROCARGS2` (the `process-info*` narrowing *and* the `kern.procargs` prefix deny; each alone leaves it readable: measured in 011c-1). Added: `(deny sysctl-read (sysctl-name-prefix "kern.proc."))`, without which `KERN_PROC_ALL` lists every process of the machine **with its name** (measured).
- **Point 6, replaced:** `kill(-1, SIGKILL)` inside the profile kills the sandbox's members **and the sender** (measured: the worker stand-in died with signal 9, and so did a helper). It is therefore not used. K is the **membership kill loop**: list every pid (`proc_listallpids`, which needs `(allow process-info-listpids)` without a target: no restricted listing exists, measured), keep those `proc_pidinfo` can read (exactly the members under point 4's rules: 5 of 5, no outsider, measured), skip the worker itself, `SIGKILL` each, and repeat until a listing finds no member or LIM-O2 passes (then `tree_kill_incomplete`, as on Linux). Re-parenting cannot escape membership, a reused pid of an outsider cannot be hit (the kernel refuses to signal it), and a fork storm converged in 0.16 s (measured). The primitive is `seatbelt_membership`, **`enforced`**. Consequence: macOS no longer needs `accept_best_effort = ["K"]`; the mechanism of RFC 011 §5 stays for any platform where a mandatory clause is best-effort. The cost, stated in the threat register: host tools can learn the *numbers* of every pid on the machine (not names, owners, parents or arguments).
- **Point 7, settled:** the same listing gives M (`rss_watchdog`: the members' summed resident size above LIM-H2) and C (`process_count_watchdog`: the members' count above LIM-H3), polled every LIM-H6, both `best_effort` (a poll can miss a short excursion). Listing 544 pids and reading the members took under 10 ms (measured).
- **Point 8, settled to the measured minimum:** the system part of the read set is `/usr`; `/bin` and `/sbin` (shells and tools that builds `exec`); the root directory itself, as a literal (the loader needs it); `/private/etc/ssl/openssl.cnf`; `/System/Library/CoreServices/SystemVersion.plist`; the random, zero and null devices; the active developer directory from `/private/var/db/xcode_select_link` (else `/Library/Developer/CommandLineTools`) and, for an Xcode, its `Contents/SharedFrameworks`; `xcrun`'s cache file `xcrun_db` in the per-user temporary directory, as a literal (the directory holds other programs' files and is not readable as a whole); `/Library/Apple/usr/libexec/oah` where it exists (Rosetta's runtime: without it a translated tool aborts; measured). Not in it: `/System` as a whole, `/private/etc` as a whole, any file of the home directory (none was needed, measured). **One mach service:** `com.apple.bsd.dirhelper` (one of two interchangeable ones; the other, `opendirectoryd.membership`, can consult a network directory on a managed Mac and is refused). Exec is allowed on the read and write sets (a build runs what it built). `file-read-metadata` stays unfiltered, as Landlock does not cover metadata either: a host tool can learn whether a path exists, on both platforms (threat register). Additions found when the implementation runs the whole suite are made one at a time, each with the failure that asked for it.
- **Point 9, settled:** the dependency step's worker adds exactly three rules: outbound TCP to port 443, a Unix-socket connect to `/private/var/run/mDNSResponder`, and `/private/etc/ssl/cert.pem` readable; no mach service (measured: `cargo fetch` succeeds with them and its sibling cannot resolve a name). Registries over HTTPS only; a git dependency over SSH is not reachable and the book says so. The offline profile denies the `mDNSResponder` socket explicitly as well, so that no later rule reopens it silently.
- **LIM-H6** stays 100 ms until the implementation measures the watchdogs.
